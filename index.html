Mapping the Sysmon Event Pipeline
From Kernel Callback to EVTX Storage
Sysmon is one of the most widely deployed host-based monitoring tools in enterprise defence environments — but its internal architecture is poorly documented. During my MINDEF cybersecurity research attachment, I mapped the complete event pipeline from the moment a kernel-level event fires through the telemetry collection layer to its eventual storage as an EVTX log entry.

The investigation involved analysing Sysmon's data collection mechanisms at the kernel level — specifically its use of kernel callbacks, ETW providers, and minifilter drivers. Using WinDbg for live kernel debugging, fltmc for filter driver inspection, registry analysis, and PerfMon for ETW provider enumeration, I validated each stage of the pipeline and identified where data could be manipulated, delayed, or dropped without triggering detection.
Kernel callback registration and ETW provider enumeration
Minifilter driver behaviour and filter attachment order analysis
Configuration filtering logic and bypass surface evaluation
Full event pipeline: kernel trigger → user-mode service → EVTX
Detection gap validation through controlled evasion reproduction
RF signal behaviour, Wi-Fi protocols, drone communication vulnerabilities
